NexusKit v0.3.0 将两个 beta 中使用和迭代的技能体系发布为正式版。共 24 个技能，按需组合；`nk-odyssey` 保持“测试中”，继续随套件分发，不作为已完成实战验收的多 agent 调度能力。

## 从 v0.2.0 升级

- 退役 brainstorm、ideate、plan、work、handoff、compound、close、simplify 八个旧入口及集中 conventions 层。
- 需求讨论用 `nk-grill`，大型未知目标用 `nk-wayfinder`；已定内容经 `nk-to-spec` 成文、`nk-to-tickets` 拆票。单个明确任务直接用 `nk-implement`，无需先走完整规划流程。
- `nk-review` 做需求符合性、实现正确性、简洁性与可维护性三轴审查；`nk-spec-close` 负责 spec 整体验收，`nk-pr` 负责分支交付、授权合并与清理。有效审查结论按范围复用。
- Linear 管内部需求与任务，GitHub Issues 管外部反馈，OpenViking 管背景与经验，Git/PR 管交付事实。术语与关键决定保留在 CONCEPTS.md 和 docs/adr/，不再维护 current 状态文档或 solutions 流程。
- 推荐搭配 Linear 和 Orca；Orca 可选承载工作树与实施 agent 派发，探索与审查仍走原生子代理。项目接入使用 `nk-init`。

## 相对 beta.2 的调整

- `nk-commit` 移除对子代理提交的角色限制，提交责任由调用流程决定；`nk-init` 固定写入 docs/agents/issue-tracker.md，与消费方路径一致。
- `nk-tdd` 在确认测试接口时说明各接口能发现与无法覆盖的问题，保持测试取舍规则集中维护。
- `nk-wizard` 同步 Matt 上游模板修复：Readline 输入、EOF 退出、文件权限与符号链接保留、浏览器失败提示、清屏回退、运行函数包装；保留 NK 的跳过项未完成提示。上游的 Shell 引号编码会使 dotenv 消费器截断含单引号的值，本版不迁移该部分，沿用原始单行 KEY=VALUE 格式。
- README 新增项目徽章、导航、配套工具推荐与 Matt Pocock 鸣谢，统一正式版说明；插件版本均为 0.3.0。

## 验证与适用范围

- 用户已在两个 beta 中持续使用实施流程，并反馈 `nk-implement` 工作正常、对过度防御性编程有所改善。这是实际使用反馈，不代表所有客户端与技能组合均已覆盖。
- 本机仓库五项检查、Bash 模板语法与 diff 检查通过；wizard 的环境值读写、默认值、EOF、完成提示及浏览器失败提示已做隔离行为验证。
- wizard 的交互式方向键、符号链接与 Unix 权限未做完整实测；环境值须符合目标应用的 dotenv 格式，尚不保证特殊字符同时兼容 dotenv 与 Shell source。仓库机械检查不证明客户端执行效果。
- `nk-odyssey` 尚缺真实任务的完整验证，尤其是 Orca 与不同 agent 的组合，后续随实际使用继续打磨。问题修复与小幅完善通过 0.3.x 迭代。
