NexusKit v0.4.0-beta.4 是 v0.4.0 的第四个预发布版，把 issue tracker 的建图规则收敛成一套可执行的最小约定，把审查挂进 checkpoint，并让 `/nk-init` 在项目内生成自包含的建票文档。用途仍是固定真实客户端安装验收的版本基线；不代表客户端加载与执行流程已经通过验收。

## 主要变化

- **`references/issue-graph.md` 重写**：从「层级模型 + 12 条规则」改为命令式规则——工作单位单层父子、三种边（parent-child / blocks / provenance）、checkpoint 收口、审查、关闭、命名，以及 beads / Linear / GitHub 的对应关系。取消 root epic、workstream 层和子票数量上限。
- **`planning-and-task-breakdown`**：检查点模板增加一轮 `code-review-and-quality` 审查，人工评审叠加其上；外部 tracker 的图规则改为优先读项目内的 `docs/agents/issue-tracker.md`。
- **`code-review-and-quality`、`incremental-implementation`**：移除建票规则，回到上游形态。审查只产出报告，建不建票、怎么 triage 由使用者决定。
- **`/nk-init`**：选了外置 tracker 时生成 `docs/agents/issue-tracker.md`，写入规则全文（末尾速查按所选工具替换），规则文件里只留一行指针。指针指向项目内文件，插件升级或换版本都不会断。

## 与 beta.3 的关系

beta.3 发布说明里描述的 root epic / phase epic / workstream 模型、review 挂被审层级、finding 作子票等规则已作废，以本版为准。

## 分发与维护检查

- 检查覆盖链接、引用、入口大小、分发、frontmatter 与 artifact 路径；CI 在 PR、main 与版本 tag 上覆盖 Windows/Linux，版本 tag 另校验版本号与 release notes。
- 技能数量、命令数量与子智能体数量不变：25 个技能、10 个命令、5 个 agent。

## 验证与限制

- 仓库机械检查六项通过，检查器单测通过。
- 建票文档由 `/nk-init` 生成；本版只验证了生成内容本身，尚未在第二个项目跑完整初始化。
- 未做真实客户端的安装验收，机械检查不证明客户端执行效果。

## 后续路线

1. 在真实项目中跑一次 `/nk-init`，确认生成的 `docs/agents/issue-tracker.md` 与建票流程合手。
2. 按新的约定走完一次 phase 收口，观察 checkpoint 与 finding 的实际流转。
3. 验收通过后发布 v0.4.0 正式版。
