NexusKit v0.4.0-beta.1 是 v0.4.0 的预发布版，技能主体切换到 addyosmani/agent-skills 简体中文版，完成 vendor 与逐技能审阅。用途是固定真实客户端安装验收的版本基线；不代表客户端加载与执行流程已经通过验收。

## 主要变化

- 技能主体：25 个技能平铺在 `skills/`，技能名、目录与 H1 保留上游原样；frontmatter `description` 换成上游英文原文；本地改动限于术语统一、交叉引用修正与少量流程适配，逐技能记录见计划文档的审阅表。
- 命令层：9 个上游 Claude Code 命令改为 `nk-` 前缀并移除 `agent-skills:` 前缀；新增 `/nk-init` 项目接入命令，确认规则文件、产物落点、外置工具与子智能体模型后写入项目约定，仅手动调用。
- 子智能体：保留上游 4 个 persona 并补 `model`；新增 `doubt-challenger`，用于对抗式证伪复审。
- 旧版 23 个 `nk-*` 技能封存于 `archive/v0.3.x-nk-skills` 分支。E 组提回裁定已定 13 个，剩余 10 个待 beta 试用后裁定。
- 客户端矩阵：Claude Code 为主体，提供插件与市场清单；Codex 安装方式因技能体积超出读取上限废止；Kimi 插件本期不开发。

## 分发与维护检查

- 插件清单与两个市场清单版本统一为 `0.4.0-beta.1`。
- 检查覆盖链接、引用、入口大小、分发、frontmatter 与 artifact 路径；CI 在 PR、main 与版本 tag 上覆盖 Windows/Linux，版本 tag 另校验版本号与 release notes。
- artifact 路径检查覆盖 `SPEC.md`、多模块 `spec/` 与 `tasks/plan.md` / `tasks/todo.md`，防止命令与技能中的落点漂移。

## 验证与限制

- 仓库机械检查通过；检查器单测通过。
- 未做真实客户端的安装验收，机械检查不证明客户端执行效果。
- 未在真实空项目中验证 `/nk-init` 的七问交互、幂等重跑与写入结果。

## 后续路线

1. 在真实项目中安装并试用 beta，收集技能路由、命令执行与项目接入的问题。
2. 根据试用结果完成 E 组剩余 10 个技能的提回裁定；如有提回，补充适配与检查。
3. 验收通过后发布 v0.4.0 正式版。
