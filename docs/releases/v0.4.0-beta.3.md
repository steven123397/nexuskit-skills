NexusKit v0.4.0-beta.3 是 v0.4.0 的第三个预发布版，在 beta.2 基线上补入上游 addyosmani/agent-skills 0.6.14/0.6.15 的其余可翻译修正，并新增 issue tracker 的图结构规则。本版在首次 beta.3 发布后重打过一次，把上游回填一并纳入。用途仍是固定真实客户端安装验收的版本基线；不代表客户端加载与执行流程已经通过验收。

## 主要变化

- **新增 `references/issue-graph.md`**：给出 issue tracker 的层级模型与关联规则，覆盖 root epic、phase epic、workstream epic、执行任务、checkpoint gate、review 与 finding；包含 12 条建图规则、建票前检查清单、5 步建图流程，以及 beads 到 Linear / GitHub Issues 的映射表。
- **`planning-and-task-breakdown`**：重写外部 tracker 的说明，补充五条图结构摘要——一个 plan 一个 root epic、phase 必须是 issue、checkpoint 是叶子 gate、容器子票不超过约 10 张、除 root 外每张票必须有父。
- **`code-review-and-quality`**：新增第 6 步，规定 review 本身作为一张票挂在被审层级，finding 作为它的子票，不修的 finding 记录理由与去向。
- **`incremental-implementation`**：范围外发现不再留在 root，默认挂当前 phase 的 review 或对应的 program epic。

## 上游 0.6.14 / 0.6.15 其余回填

- **示例修正**：Idempotency 错误结构、Playwright 按文本定位、Jest 30 文件过滤、Lighthouse 指向 localhost、axe CLI、web-vitals attribution 别名、ErrorBoundary children 类型、adapter 方法、前端 TaskList 与空状态、`role="status"`。
- **触发词**：`code-simplification` 与 `git-workflow-and-versioning` 的 description 补「代码或 diff 被内联粘贴时同样适用」。
- **语义更新**：`context-engineering` 的压缩阈值改为随 host 而异；`doubt-driven-development` 要求保留矛盾证据；`test-driven-development` 要求崩溃与回滚测试触达真实边界。
- beta.2 已回填的安全扫描、质量门禁与命令调用权限不再重复。

## 分发与维护检查

- 检查覆盖链接、引用、入口大小、分发、frontmatter 与 artifact 路径；CI 在 PR、main 与版本 tag 上覆盖 Windows/Linux，版本 tag 另校验版本号与 release notes。
- 技能数量、命令数量与子智能体数量不变：25 个技能、10 个命令、5 个 agent。

## 验证与限制

- 仓库机械检查六项通过；检查器单测通过。
- 新增规则来自一次真实项目的 issue 图盘点，属于经验归纳，尚未在第二个项目中验证。
- 未做真实客户端的安装验收，机械检查不证明客户端执行效果。

## 后续路线

1. 在真实项目中按新规则建一次完整 issue 图，验证 phase、checkpoint 与 review 的挂载是否顺手。
2. 待 vinvcn 中译本跟进到 0.6.14+ 后，补齐其余样例与触发词修正。
3. 根据试用结果完成 E 组剩余技能的提回裁定；验收通过后发布 v0.4.0 正式版。
