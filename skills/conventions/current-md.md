# docs/current.md 格式契约

记录接手所需的现状、证据、阻断和下一步；Plan、Issue 与 Git 保留细节，current 只放可定位的摘要与指针。字段规则在此维护，写入方不复制另一份模板。nk-commit 在每次提交前按需维护；用户显式调用 nk-handoff 时可保存未完成现场。

## 字段

| 字段 | 内容与条件 |
| :-- | :-- |
| 当前状态 | 所在分支、核对基点、关联 Plan 或工作范围、已具备能力及实际验证证据；没有 Plan 或发布版本也可交接 |
| 阻断与已知缺口 | 未解决问题、外部依赖、未验证项与待确认决定；无阻断写“无” |
| 下一步 | 有可实施单元时写 Plan 路径与 U-ID；尚无单元时写建议技能与产物路径；直接需求或 Issue 写可定位的任务与引用，不补造编号 |
| 工作区未提交改动 | 有待接手或需保留的残留时必填，不限代码；写文件范围、归属、完成程度与验证状态；外来改动只说明保留，不据此接管 |
| 已排除的方案 | 可选，最多三项有证据支持的失败方案及原因；保留对接手仍有用的内容 |

**核对基点**是整理本记录时核对的提交，不是承载交接文件的最终提交。无初始提交写“尚无提交”。接手时 HEAD 不同，核对期间的实际变化；新增交接提交或 amend 可导致差异，不能只因哈希不同就认定异常，也不假定旧基点仍是 HEAD 的祖先。兼容旧记录中的 HEAD 字段，将其作为待核对的历史快照，不为更新哈希反复提交。

## 简短模板

按实际情况填写，不照抄示例结论；可省略不适用项。

```markdown
# 当前状态

- 所在分支：<分支>
- 核对基点：<整理时核对的提交，或尚无提交>
- 工作范围：<Plan 路径或任务>
- 已具备能力：<已实现的结果>
- 验证：<实际命令、结果及适用范围>

## 阻断与已知缺口

<问题、未验证项和待确认决定；无阻断写无>

## 下一步

<Plan 路径与 U-ID；无单元时写技能及产物路径或具体任务>

## 工作区未提交改动

<有残留时写文件、归属、完成程度、验证状态>
```

## 内容维护

- 更新字段而非追加日志；先读旧内容，保留仍有效的信息，仅凭当前事实移除已失效项。
- 通常不超过 40 行，短任务不凑行数；必要信息较多时优先指向既有产物，不为限行删去关键阻断。
- 只记录可核实事实，区分用户决定、代码推断与 Agent 建议。下一步可以给出依据明确的建议，不冒充用户指令。
- 验证写实际命令、结果与未验证边界，复用仍适用的证据，不把静态阅读或模拟写成真实运行。进度以交付提交为准，不复制 Plan 或 Issue 清单。
- 不记录凭据或无关个人信息。文件承担信息契约，不自行触发提交；提交前的更新与入库由 nk-commit 统一执行；阻断可即时登记，但不触发自动提交或 handoff。
