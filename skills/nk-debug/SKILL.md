# /nk-debug

查清异常的原因，并在请求包含修复时完成修复。已有明确方案的实施单元走 [nk-work](../nk-work/SKILL.md)；本技能自行完成调查和修复，不委托其内部流程。

按阶段读取材料，已完整掌握且未变化的材料复用，不为进入下一阶段重读。

## 1. 明确问题与调查范围

结合项目指导、已有 current 和输入，确认症状、期望行为、发生环境及请求是仅诊断还是包含修复。输入为 Issue 时读取正文和评论，保留原始问题引用；不为凑记录新建 Issue。先利用已有上下文，只有缺失信息真正阻断调查时才提问。

读取 [调查流程](references/investigate.md)，完成分诊、复现与观测、环境核对、因果追踪和假设检验。明显的小缺陷可省去无关的深度调查，仍需确认行为和验证修复；不按行数决定可信度。

以下材料只在需要时由本入口选择，调查材料不再递归加载规则：

| 当前需要 | 读取材料 |
| :-- | :-- |
| 缺少可用复现、现有回路难以反复运行，或大场景阻碍定位 | [复现回路工具](references/reproduction.md) |
| 性能回退、间歇性失败、竞态、跨系统边界、回归二分或常规追踪停滞 | [调查技术](references/investigation-techniques.md) 中对应章节 |

复现是后续验证的依据，必须区分实际观察和推断。无法在本地复现时，记录尝试与缺失条件；可继续读取已有日志、样本和代码补证，不能把推测说成已确认。需要额外环境、生产操作或基于未证实假设试修时，先说明缺口并取得对应授权。

## 2. 汇报诊断，确定是否修复

给出触发到症状的因果链、代码位置或外部观测证据、已排除的解释、建议修复范围，以及应复用或补充的验证。说明既有测试为何没挡住问题；发现已有相关修复时先给出其引用，避免重复劳动。

- **仅诊断**：报告结论和置信边界，进入第 4 步汇报出口，不修改产品代码或制造提交。
- **已请求修复且根因证据充分**：直接进入第 3 步，不重复询问是否修复。
- **请求未明确授权修复**：先呈现上述诊断，再询问是否修复或停在诊断。
- **修复会推翻有意设计的行为或既定决定**：说明冲突并请求决定，不把需求变更包装成 bug 修复，也不通过改测试预期强行变绿。设计需要重议时可建议 nk-brainstorm，不因涉及多文件就认定要重做设计。

根因仍未确认时，继续有信息增益的调查；反复受挫则按调查材料核对卡点。获准试修也须标明假设，不把临时缓解宣称为根因修复。超出授权的选择在无人值守时暂留并记录，不自行替用户改变契约。

## 3. 修复并验证

读取 [修复流程](references/fix.md)，核对工作区归属，选择已有测试或真实复现，完成最小修复、原始场景验证与影响范围内的回归检查。一次只检验一个因果解释；同一修复可以涉及多个相互依赖的文件。

根因模式存在多条实际复发路径，或涉及可能造成严重后果的危险操作时，按需读取 [分层防御](references/defense-in-depth.md)。只补本次缺陷所需的保护，不扩为全仓重构。生产事故或反复出现的模式应解释引入原因和覆盖缺口；验证后有长期价值时建议 [nk-compound](../nk-compound/SKILL.md)；已有沉淀授权则在提交前传入对象、证据、决定、关联交付与授权范围，成果返回本流程统一提交。不自动触发复盘或审计。

清除本次临时探针和放弃的改动，核对最终 diff。**提交前调用 [nk-review](../nk-review/SKILL.md)**，提供本次修复范围、根因、预期行为与已有验证证据。review 返回审查报告，由本技能直接修复查证成立的问题，无需逐项询问；随后补跑受影响的检查，对修复及新增风险做针对性复核。未变化且仍适用的证据直接复用，不机械重跑整轮审查与验证。测试通过不等于审查完成，未完成审查或仍有阻断时不得进入正常交付提交。

## 4. 提交或汇报结束

可交付修复将文件范围、审查结论、已有验证命令与结果、根因摘要、阻断及下一步交给 [nk-commit](../nk-commit/SKILL.md)，由其核对 current 并同次提交。证据仍适用时复用；用户要求只修不提交时遵循，不推送或自动调用 handoff。

任何出口都先检查本次临时探针：能安全清理的清理，仍需保留的说明路径与用途，不触碰外来文件。汇报问题、根因或剩余假设、实际改动、验证与未验证项、提交或暂留状态及下一步。仅诊断是有效完成方式；受阻退出须明确未完成。

受阻时说明当前证据、缺失条件和可选下一步，由用户决定继续调查、调整方向或另行调用 handoff；不因受阻结束自动更新 current。

调查中确需持续跟踪的疑难缺陷或范围外发现，按 [产物分流](../conventions/artifact-lifecycle.md) 第四章处理。有落档授权时将对象、已有证据、仓库与授权范围交给 [nk-to-issue](../nk-to-issue/SKILL.md)，返回后继续本任务；缺授权只建议。已有记录复用或补充，不重复调查建票，不固定在诊断结束时转 Issue。

## 调查中的约束

- **证据脱敏**：命令构造时将凭据留在环境变量中。可能含密钥的输出先落到受控临时位置，仅展示脱敏片段；不在报告或提交中保留凭据。脱敏后不足以判断时请求协助。
- **只读子代理可选**：客户端允许且调查对象独立时可派发，给出具体假设和待取证项；不改代码或提交。按 [结果体量约定](../conventions/subagent-results.md) 返回观测、反证、位置与未验证项，由主会话核对；失败时改为串行调查，不因等待代理自动结束或提交。
