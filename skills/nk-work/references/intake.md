# 输入与范围

先根据收到的输入确定本次要完成的实施单元，再检查是否具备开工条件。无需先通读整个 Plan。

## 输入分流

- **Plan 单元**：根据 U-ID 或 Plan 路径定位文件；先扫描标题，再读取 Goal、当前单元、直接依赖、Verification Contract 和 Definition of Done。
- **Issue**：读取 Issue 的背景、复现或验收条件；认领与关闭按项目的 Issue 约定执行。
- **空输入**：读取目标仓库 `docs/current.md` 的“下一步”第一项；没有下一步就请用户指定。
- **直接需求**：微小改动直接做；范围清楚的中小改动列出短清单后做；跨模块、边界不清或技术选型未定时，建议先用 `/nk-plan`，由用户决定。

## 开工前检查

1. 当前代码、接口和上游单元是否已经存在；不存在或与 Plan 根本矛盾时报告阻断。
2. 测试工具链是否可运行；不能运行时记录替代验证和未验证边界。
3. 工作区改动是否已登记；外来脏文件可以存在，但不得暂存或提交。
4. 直接需求若实际改变范围、外部契约或不可逆后果，先进入确认流程。

## 完成条件

完成目标、具体验收和验证边界已经从输入中可判定；若 Plan 只有方向没有可执行的输入输出、文件范围或验证标准，退回 `/nk-plan` 补全。
