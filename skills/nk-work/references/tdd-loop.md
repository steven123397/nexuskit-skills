# 实施循环与测试证据

实施单元涉及代码改动时，按以下步骤理解现状、实施并验证。在完整满足需求、充分理解代码并保持验证强度的前提下，减少不必要的实现与维护负担。

## 1. 理解现状，选择最小充分方案

先读需求、Plan 引用的代码和本次触及的真实调用链，确认边界与失败方式；沿用项目命名、类型、错误处理和模块约定。查找现有测试及相似实现，独立的只读检索可合并。能力若已存在并满足验收，实际验证后返回主流程，不重新实现。

在已定需求与方案范围内，按以下顺序寻找足够的实现；找到满足全部约束的选项即可停止，不展开无关调研：

1. 省去需求没有要求、也无现有使用方的推测功能、配置和扩展点；不擅自缩减明确需求。
2. 复用仓库已有且行为匹配的能力。
3. 使用标准库、平台或框架原生能力，以及已安装且适用的依赖。核实目标版本、输入边界、错误语义与兼容性；不能只因接口相似就替换。
4. 都不满足时，新增最小必要实现；新增依赖或抽象应解决实际的职责、隔离、复用或可测试性问题，而不是为假想未来预留框架。

优先减少重复状态、分支、包装层和自维护代码；不以一行表达式、文件数或净删行数为目标。不削弱信任边界校验、防数据丢失、安全、无障碍与必要的性能或兼容要求。已知容量或算法上限若是有意取舍，就在相关位置说明上限和何时需要升级；超出已定约束时报告，不能先交付缩水版本再询问。

修复缺陷时追踪共享函数的相关调用方，尽量在根因所在层修复一次；核实其他调用方的语义，不把只适用一个入口的限制强加给全部入口。

## 2. 修改行为前选择证据策略

查找导入、引用或按命名对应的测试；从 Plan 已列测试出发，补查遗漏的覆盖。测试调整与行为对应：新增行为补覆盖，改变行为更新断言，删除行为才移除或更新失效测试。

| 现状 | 行动 |
| :-- | :-- |
| 已有测试已因目标行为失败 | 复用该 Red 证据，不另写重复回归测试 |
| 已有测试断言旧行为或错误期望 | 修改现有断言，在改实现前确认预期失败 |
| 测试过度 Mock 或未走真实调用链 | 针对性加强现有测试，确认能暴露真实缺陷 |
| 没有覆盖该行为 | 增加最小聚焦失败测试；需要保留既有行为时先记录特征测试基线 |
| 不适合测试先行 | 先记录理由与替代验证，再执行改动；不能因“少写代码”而降低验证要求 |

补全适用场景的输入和预期结果：正常路径、边界或并发、非法输入或权限拒绝、下游失败、跨层集成。Plan 只写“验证正确”不够。琐碎重命名、纯配置、纯样式、生成物或纯手动界面可以说明豁免理由，但必须留下替代验证结果。

## 3. 垂直切片 Red → Green

每轮选择一个可观察行为的公开接缝，先写或修改一个测试，单独运行并确认因预期原因变红，再写让它变绿的最小实现。特征测试先观察并记录当前基线。不要在同一步同时写测试和实现，不超出当前切片过度实现。

- 测试通过公开入口检验输出、持久化结果或边界副作用；内部重构不改变行为时，测试应继续通过。不要只断言私有方法和内部调用次数。
- 期望值应来自独立已知结果、需求或规格，不能来自被测代码自身，也不能在断言中重复业务算法；Mock 不能直接提供被测逻辑本应计算的结果。
- 只在外部 API、数据库连接、时间、随机数等系统边界按需替代；测试数据库可用时优先使用。系统内部计算与参与交互的模块使用真实对象。
- 真实入口能够驱动行为时，不为测试新增专用生产导出、开关、包装器或钩子；需要替代外部服务时使用已有或合理的依赖注入边界。
- 循环内不混入无关重构。实现定型后的精简与版本审查分别由对应技能负责，本循环不自动增加这些关卡。

每次显著变更后运行相关测试，必要时运行类型或编译检查；失败立即处理，不攒到最后。

## 4. 系统级因果检查

在单元完成前，按适用风险执行动作，不只口头回答问题：

| 风险 | 核对与验证动作 |
| :-- | :-- |
| 回调、中间件、观察者或事件传播 | 阅读真实代码，从改动处向外追两层，核实触发顺序和副作用 |
| 跨层交互 | 至少一个真实对象穿过相关调用链的集成测试；参与交互的内部层不 Mock，外部服务可在边界替代 |
| 外部调用前已写数据库、缓存或文件 | 追踪失败路径，测试清理、补偿或重试幂等性，避免孤立状态与重复写入 |
| 平行接口暴露同一行为 | 搜索相关入口；需要保持一致时在当前范围内补齐并验证，范围有冲突则报告 |
| 各层捕获、重试与降级叠加 | 对照实际抛出和捕获的错误类型，检查吞错、重复执行与重试放大 |

无回调、无持久化状态、无平行接口的纯叶节点改动，核实无外溢后可跳过相应检查；不为凑类别增加测试。

## 5. 验证与完成证据

运行当前测试、受影响的测试套件和项目要求的完整检查；运行适用的构建、typecheck、lint，核对无新增警告或错误。无法确定影响范围时扩大验证，而不是用一个烟雾测试代替。未配置或环境不可运行的检查如实记录，不虚构命令或通过结果。

逐项对照需求、单元验收和 Plan 留待实施解决的问题，确认已实现或明确阻断；查看最终 diff，清除调试代码、放弃的尝试和无关改动。代码看似更短或测试变绿，都不能替代需求验收。

记录实际检查过的测试、使用或修改方式、Red 或基线证据、最后验证命令和结果，以及豁免理由。对外报告与提交区分 Verified / Unverified；Mock 验证不能宣称真实外部环境已经通过。返回主流程处理文档、提交或阻断交接。
