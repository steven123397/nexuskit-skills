# 协作复盘

仅在入口识别到明确复盘意图或已有持续授权时使用。目标是改善未来协作，输出有证据的改进候选，不要求每次产出 solution，也不直接实施建议。

## 取证

用户指定会话或材料时读相应原始记录；默认使用当前会话。仅补与复盘对象相关的日志、Git 变化、项目指令与检查配置，不扫描无关历史会话。材料不可达时说明缺口，不凭最终 diff 编造探索过程。区分真实发生的行为、用户反馈、推断的原因和未验证建议。

## 选择有信号的视角

| 实际信号 | 核对什么 | 建议去向 |
| :-- | :-- | :-- |
| 找文件或规则耗时、遗漏隐含依赖 | 现有入口和引用能否定位材料 | 最小导航指针，避免复制整份规则 |
| 错误本可机械发现 | 先读项目 lint/typecheck/test 命令及 hook/CI，区分没有检查与已有检查未接通或失效 | 优先建议接通或修复确定性检查，不用长提示词替代 |
| 审查漏掉一致性问题 | 是可匹配的语法/路径规则，还是跨文件语义判断 | 前者交给检查器，后者交给项目现有审查规则；不强制新建规范文件 |
| 指令很长、互相冲突或没有改变行为 | 是否重复、过时、无具体作用，哪些内容只在特定阶段需要 | 精简或按需加载建议，不借复盘直接修改技能 |
| 工具调用昂贵或重复 | 实际调用、返回体量、重复读取及可复用证据 | 调整调用方式或工具输出，说明收益依据与代价 |
| 缺日志、来源或必要访问 | 具体缺失怎样影响判断，现有只读渠道是否够用 | 最小可观测性或信息访问建议，不自动扩大权限 |

不要求逐项凑发现。检查器缺失可以是风险信号，但先说明项目为何需要、现有机制能否覆盖。只复盘被指定的范围，不顺带审计全局 Agent 环境。不要把一次失败推导成通用禁令，也不要把成功归因于没有证据支持的某个动作。

## 返回入口

按影响与复发风险排序，每项给出：实际观察与来源、原因及置信边界、具体改进、适用条件与代价、是否已采纳/实施/验证。已有机制足够时明确不新增。

未实施建议留在对话，不写成已成立经验，不自动创建 Issue。用户另行授权的实施交给相应流程。已形成合格知识的候选返回入口做准入判断；复盘授权本身不强制建档或批准修复。
