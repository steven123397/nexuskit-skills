# 发布日扫尾

仅明确的发布日请求加载。普通收尾不打 tag；沿用目标项目的版本规则、发布分支及授权范围，不自行创造版本号或远端发布流程。

1. **确定发布对象**：核对分支、目标版本、待发布提交范围和项目发布条件。缺少会改变发布对象的信息才问；已有决定直接复用。外来工作区变化不得混入。
2. **漏网检查**：检查发布范围内尚未清理的已交付 Plan/审查记录，以及未消费、已消费未交付、已消费已交付三类发想的处置；核对关联 open Issue 是否确实仍有未处理事项。合法保留的记录、明确延期的 Issue 不自动构成漏网。
3. **处置缺口**：需要提炼或删除时返回 close 主路径，对明确对象补收尾；不在此复制清理流程。交付阻断或未决材料保全问题未解决时停止发布。仅不影响交付的维护遗漏，可按用户已同意的延期决定留存并在 release notes 披露；建票本身不构成放行。
4. **Release notes**：依据实际交付与已知限制写入项目指定位置，默认 docs/releases/。不把未实施或未验证项写成已交付，不将收尾与发布视为同一件事。
5. **提交与 tag**：将 release notes、相关维护及证据交给 nk-commit，先完成本地提交，再核对待标记提交并按项目规则创建已获授权的 tag。禁止对旧 HEAD 先打 tag 再提交说明；已有同名 tag 核实其指向，不移动或覆盖。不自动 push、创建远端 release 或部署。
6. **返回入口汇报**：返回检查范围、保留/延期项、release notes 路径、提交与 tag 的真实结果。用户只要求准备或禁止提交时保留草稿，不创建 tag；任何一步失败都说明发布尚未完成，恢复时复用已成功成果。
