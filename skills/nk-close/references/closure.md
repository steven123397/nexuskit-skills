# 收尾对象与处置

由入口按阶段使用本材料：先定界与预检，合并前检查通过后再承接遗留、提炼和清理。各阶段结果交回入口，不自行提交或扩大范围。

## 定界与证据

读取 current、项目流程、相关 Plan 和 Git 状态。列出合并目标、累计变更基线、当前 HEAD 及纳入的工作区内容；目标取用户或项目指定的实际合并分支，不能把同名远端功能分支的 upstream 当作合并目标。用 merge-base 定位累计 diff，并核对提交清单；目标不可判定时询问。目标推进时检查其与本次接口的变化，不把分叉点审查误称为已验证合并结果。

单分支项目按 Plan、关联提交与路径定界；起点或混杂改动无法可靠分离时报告，不把同一时间段所有工作都归给该 Plan。Plan 在开分支前提交、多个 Plan 共用 U1、合并提交或 squash 都可能使标题搜索不可靠。

建立本次临时处置清单（可在对话，不强制新建文件）：产物、归属/消费者、交付状态、验收与审查证据、未决事项、拟采取动作。归属依据包括 Plan 引用、提交变化、Issue 关联和实际内容；分支已有文件不一定属于本次，基线中已有 Plan 也可能是本次主要输入。

- 验收对照 Plan 的整体目标、当前单元和验证契约；没有 Plan 的临时工作对照明确需求与修复证据。不根据提交标题宣告通过。
- 核对必要单元审查是否完成、报告覆盖的快照是否仍适用；零发现合法，缺报告不自动等于零问题。项目不要求该类审查时注明依据，不凭空增加门槛。
- 整体集成/验收证据按项目与 Plan 要求核对；未运行不得记为通过。用户明确调整交付范围或接受验证限制时记录实际决定，不能伪造证据或掩盖未完成条件。
- 工作区和暂存区的后续工作、外来改动与收尾改动分开；同文件混杂且无法安全区分时先报告，不能整文件夹带。

## 遗留承接与 Issue 兜底

消费 review 公共返回的报告、结论、发现及覆盖缺口。状态为“待修”的发现需修复或有明确延期决定；“遗留-转 Issue”须核实已有承接记录；“已修复”复用适用证据。P0 或仍违反本次交付条件的事项保持阻断，不以建票放行。

推迟的 Plan、未消费发想按入口的用户决策规则处理。转 Issue 前查重并保留行为目标、未竟事项、已有证据与来源；转到后续工作时确认目标位置及接手信息已写入，不仅口头说“以后处理”。远端不可用时报告写入失败，除非用户同意降级，不把失败冒充已落档。

从本次提交正文、相关 Plan 和审查记录收集 Issue 引用，结合仓库与链接去重；用当前 shell 原生搜索或工具逐条读取，不硬套 Bash 管道。区分 Issue、PR、历史提及和当前交付覆盖：

- 已满足完整完成定义且有对应提交证据：按 Issue 约定关闭并记录依据。
- 部分完成或明确延期：保留 open，关联已有承接及原因；不重复创建。
- 不属于本次：保持不动并排除。

外部写入以实际成功为准；失败保留待办及源材料。恢复收尾时先核对现有 Issue，避免重复评论或建票。

## 知识候选

按价值密度检查将被清理的材料：关键决策理由和被否方案、排障因果与失败尝试、新稳定领域术语。代码本身、例行选型和纯进度不要求建档。

先检索同领域 solution，记录“已有覆盖 / 候选缺口 / 不值得沉淀”。候选经入口调用 compound 判断准入、写入与最终自检，不能绕过入口自己套模板。用户调用收尾所需的知识保存属于该次范围；未采纳建议不写成已验证经验。无法确定是否含独有长期价值时保留源材料并说明疑点，不以“宁缺毋滥”为由直接删除。

## 删除矩阵与引用

| 产物 | 处置 |
| :-- | :-- |
| 已交付 Plan | 遗留与独有知识已承接后删除；仍被活跃工作依赖时保留或先迁移依赖 |
| 未完成/推迟 Plan | 保留；用户决定转移时先确认承接成功，再按该决定处理原文件 |
| 已处置审查记录 | 保留范围、快照、结论与验证限制的可追溯依据后删除；尚有未承接发现则保留 |
| 未消费发想 | 复用已有决定；否则询问保留、转 Issue 或删除 |
| 已消费、对应工作未交付 | 保留 |
| 已消费、所有依赖工作已交付 | 提炼独有价值并核对引用后删除 |
| 被多个 Plan 共用的发想 | 只要仍有活跃消费者就保留，不按当前分支单独删除 |
| 被长期文件实质引用的过程材料 | 引用不代表实施已交付；先迁移所依赖内容并修复引用，无法完成则保留 |

删除前搜索仓库入站引用，并检查跨产物的相对链接；装饰性引用可清理，实质内容移到稳定去向后再重定向。Git 历史不是现行文档的有效链接替代品。不得删除 solutions 或 CONCEPTS 来完成过程产物清理。

已提交材料可由历史追溯；未提交的新报告若必须清理，先把必要证据并入本次保留产物或提交说明，并由主会话确认信息完整。清理失败时报告实际状态，不继续宣称完成。
