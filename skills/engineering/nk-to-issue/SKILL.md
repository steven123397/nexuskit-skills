把当前发现核实并整理成一条可接手的 GitHub Issue。GitHub Issues 记录外部问题；内部 spec、tickets 与执行安排在 Linear，归 `nk-to-spec`、`nk-to-tickets`。**记录不等于安排执行**：本技能只核实与落档，不开分支、不认领、不开始修复。

用户说"把这个记成 Issue"即为落档授权，沿用明确的持续授权，不额外确认一次。

## 核实

复用当前会话或调用方已有的现象、目标行为、证据、历史结论与目标仓库，不重复整理；材料有缺口才补。从项目配置与明确链接核对目标仓库；Issue 编号须关联该仓库，PR 不是 Issue。

- **Bug**：核对已有观测、代码依据和复现结果是否仍适用。缺证时定向读相关代码；必要且可安全执行时做最小复现——可能改动真实数据、外部服务或工作区时，先确认授权与隔离条件。区分**已确认**与**未能复现**：后者如实写明已尝试的内容、缺失条件和置信边界，不写成已确认缺陷。
- **需求**：写清目标行为、价值、范围与非目标；这里不做完整方案设计，进入实施前另行走 spec。
- **已有 Issue 编号**：优先读取该条目及相关讨论，不重新问已解决的问题，在已有记录上补充，不另建同题记录。

日志与样本脱敏；凭据和无关个人信息不进记录。

## 查重

落档前定向搜索相关 open/closed Issue 与代码现状，按概念和行为匹配，不只匹配措辞；复用已有检索覆盖，不扫描无关全库。

| 结果 | 动作 |
| :-- | :-- |
| 已有同题记录且无新信息 | 返回链接与覆盖理由，不重复创建或评论 |
| 已有同题记录且有新证据、范围或复现信息 | 在授权范围内补充既有记录 |
| 需求已实现且覆盖请求 | 给出代码依据并结束；存在行为差异或回归时按真实缺口继续 |
| 历史上否决或已决定不做 | 核对当时理由是否仍适用，说明后结束；新证据或条件变化支持重议时交用户决定，不静默推翻 |
| 无同题记录且值得跟踪 | 创建新记录 |

同题 Issue 已关闭但出现回归或新条件时，说明差异，按项目惯例与授权选择补充、重开或新建关联问题；没有相应授权不自动重开。查询失败不等于不存在：说明查重缺口，不盲目重试创建。

## 落档

写作原则——Issue 落档后代码会继续演化，接手者可能毫无现场上下文：

1. **持久性优于精确**：用接口、类型、行为契约的名字定位问题，不引用文件路径和行号——它们会过期。
2. **行为而非步骤**：描述系统应该做什么，不写实现步骤；接手者会重新探索代码并自行决定实现方式。
3. **完成定义可独立验证**：若写完成定义，每条单独可测，让接手者知道什么时候算完成。
4. **范围边界明确**：写清不做什么，防止接手者镀金或误伤相邻功能。

标签只用 GitHub 默认的 `bug` / `enhancement` 表达类型，不设状态标签——状态由 Issue 自身的 open/closed 与后续关联承载。条目格式：

<issue-template>

**Category**：bug / enhancement

**Current behavior**：现状；bug 写损坏的行为，enhancement 写现状基础。

**Desired behavior**：完成后的预期行为，含边界与错误情况。

**Key interfaces**：涉及的接口/类型/配置形状及需要的改变；不知道就省略本节。

**Done definition**（可选）：每条可独立验证；构想类不强造本节。

**Out of scope**：明确排除的相邻工作。

**Evidence**（bug 必填）：核实结论（已确认 / 未能复现）、复现步骤、脱敏后的报错摘要。

</issue-template>

琐碎小项可以只写标题加一句预期行为，不强套全格式。小节标题用英文锚点，正文语言随项目惯例。

- **有 GitHub 远端且获写入授权**：新事项创建 Issue；既有事项默认追加有增量的证据评论，不覆盖原描述和他人内容，用户明确要求改写正文时保留仍有效的讨论与边界。
- **无 GitHub 远端**：写入或更新 `docs/agents/issue-tracker.md` 记录的本地待办位置（未配置时默认 `docs/backlog.md`），先查重、保护已有条目；说明文件范围与未提交状态，随下一次相关交付入库。
- **网络、认证或权限失败**：报告阻断并保留草稿，不把暂时失败当作无远端另建第二套待办；请求结果不明时先查询确认是否已创建，再决定是否重试。
- **未获写入授权或只要草稿**：直接返回可审阅的正文与目标，不发送、不写文件。

写入后核对返回内容，确认目标、标题、正文与链接；不自动改 assignee、不关闭无关 Issue。收尾返回链接或位置、实际动作（创建 / 补充 / 复用 / 未落档）与未决项，由调用方继续原任务；独立调用则汇报结束。

## 边界

- 发现真正需要修复的问题也只记录；修复由用户或调用方另行交给实施入口。
- 用户决定把某条 Issue 纳入开发时，才在 Linear 关联对应 spec 或 ticket 并保留来源链接；执行进度只在 Linear，不在 Issue 里复述。
- 调查得到的建议不是实施授权；无人值守时保留未决项，不以推荐选项代替授权。
