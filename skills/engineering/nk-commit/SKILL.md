本地 Git 提交的统一入口：核对范围、保护无关工作、按项目约定写提交说明并执行。只提交，不推送、不开 PR、不维护状态文档；验证与审查由调用方持有，本技能只核对证据是否在手，不重复展开。

## 核对范围与分支

运行 `git status --short --untracked-files=all`、`git diff`、`git diff --cached`，另读范围内未跟踪文件。非 Git 仓库停止；无待提交变化直接返回，不为产生提交而制造变化。命令分别执行，`'@{u}'` 等参数正确引用。

当前处于主分支（用 `git rev-parse --abbrev-ref origin/HEAD` 确认，失败时按项目约定或 `main`/`master`）或 detached HEAD 时停止并报告，由用户决定承载分支；不在主分支直接提交，也不代开分支。有提交历史时按需读近期记录确认归属与风格，首次提交不执行依赖 HEAD 的命令。

## 保护无关工作

- 只提交本次明确范围的文件：他人或其他会话的未提交改动、无关的已暂存内容一律留在工作区。
- 同一文件混有无关变化时，先安全分离或与用户厘清范围；路径限定无法隔离文件内的混合改动，不使用交互式 `git add -p`。
- 调用方指定排除的路径保持未提交，返回时说明。

## 提交单位

- 提交单位是一个经过验证的变化：同一变化的实现、测试和配套文档一并提交；文档和规划本身也是交付物，不要求伴随产品代码。
- 能安全分开且可独立验证的变化分别提交，耦合的变化一起提交，不限定数量。
- 未完成的草稿与零散进度不入库，留在工作区随对应交付提交；无交付变化不提交。
- 修正本会话刚创建、确认未推送的提交时可 amend，仍限定路径；已共享或无法确认未共享时不自动改写历史。`git log '@{u}..HEAD'` 只说明与跟踪分支的差异，无 upstream 或引用过时不能证明未共享。

## 必要检查

提交前核对调用方提供的验证与审查证据覆盖待提交内容；适用流程要求提交前审查而证据缺失时，返回缺口，不提交。已有且仍适用的证据直接复用；仅相关内容变化或项目要求时补跑必要检查，必需检查失败不提交，退回实施。本技能不重新展开审查；测试通过不等于审查完成。

## 提交说明

风格依次遵循用户要求、项目约定、近期惯例，默认中文 Conventional Commits：

```text
<type>(<scope>): <简短成果>

<必要的原因、方案与影响>

<1–3 行真实验证证据及未验证项>
<可选的不兼容说明与 Issue 关联>
```

- **类型**：`feat` 新功能、`fix` 修复、`refactor` 重构、`perf` 性能、`docs` 文档、`test` 测试、`style` 纯格式、`ci` 持续集成、`chore` 工具维护、`revert` 回退。按变化选类型，不因为是 Markdown 就一律用 docs。
- **主题**：type 保留英文；scope 可省略，有则用稳定的模块名。中文主题用动宾短语写交付结果，不罗列文件，通常不超过 50 字符，不加句号。
- **正文**：与主题空一行，说明原因、方案或影响。验证写完整命令、结果与边界，未运行不记为通过。
- **不兼容变更**：实际不兼容时用 `!` 或 `BREAKING CHANGE:` 标明并说明迁移办法。
- **Issue**：关联用 `Refs #N`；满足全部验收及项目关闭流程才用 `Closes #N`。

## 执行与确认

完整提交信息写入仓库外临时文件，避免 shell 转义。普通提交分别执行：

```bash
git add -- <本次路径...>
git commit -F <临时说明文件> -- <本次路径...>
```

amend 改用 `git commit --amend -F <临时说明文件> -- <路径...>`。不用 `git add -A` 或 `git add .`；提交命令始终带路径限定，不吸收无关暂存内容。不跳过项目 hooks；hooks 改变了交付内容时，重新核对差异并补受影响的验证，再重试。

提交后核对哈希、主题、文件范围，运行 `git status --short --untracked-files=all` 检查残留，意外内容先报告。返回已提交结果与暂留内容及原因；不自动推送、不创建 PR、不进入下一个实施单元。
