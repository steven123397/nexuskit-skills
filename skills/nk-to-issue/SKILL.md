# /nk-to-issue

把当前发现整理成可接手的 Issue，可在当前会话直接调用，也可独立调用或由已有落档授权的流程调用。不要求另开会话；只完成核实与落档，不扩大当前任务的实施范围。

**完成条件**：创建或补充记录成功，返回可定位链接/位置、实际动作及证据边界；或明确说明已有记录足够、需求已满足或不应落档。未获写入授权时交付草稿；写入失败时报告未完成，不能冒充已建票。

**边界**：不修复产品、不开始实施、不认领任务，不因落档自动开分支、提交或交接。调查得到的建议不是实施授权。调用方决定事项是否应转待办，本技能负责核实、查重与记录质量。

短底线维护源：[决策自主权](../conventions/decision-autonomy.md)、[读取复用](../conventions/resource-loading.md)。

## 1. 接收对象与授权

识别 Bug、需求或既有 Issue。复用当前会话或调用方给出的现象、目标行为、范围、已查证据、历史结论、目标仓库与写入授权；不要求重复整理已有信息。

用户说“把这个记成 Issue”即为该事项的落档授权，沿用明确的持续授权，不额外确认一次。仅发现问题、分析请求或模型选择了本技能，不等于获准外部写入；可先核实并给草稿。无人值守时保留未决项，不以推荐选项代替授权，也不自动登记 current。

从项目配置与明确链接核对目标仓库；编号须关联仓库，不能把 PR 当成 Issue。已有 Issue 编号优先读取该条目及相关讨论，不新建同题记录。目标不明确且会影响写入对象时才问。

## 2. 复用证据并补缺

- **Bug**：核对已有观测、代码依据和复现结果是否仍适用，只补会改变判断或落档质量的缺口。缺证时定向读相关代码，必要且可安全执行时做最小复现，不固定重跑一次。复现可能改动真实数据、外部服务或工作区时先核对授权与隔离条件。未能复现可记录待查问题，但须说明已尝试内容、缺失条件和置信边界，不写成已确认缺陷。
- **需求**：明确目标行为、价值、范围与非目标；按需核对 CONCEPTS、当前 Plan、发想记录及相关实现。复杂事项可建议后续 brainstorm / plan，不在这里设计完整实施方案。
- **已有调查**：work / debug / close 已提供充分证据时直接复用；不能因为换了入口重启整轮调查。来源保留可接手线索，日志与样本脱敏，不把凭据或无关个人信息写入记录。

发现真正需要修复的问题也只记录；修复由用户或调用方另行交给 [nk-work](../nk-work/SKILL.md) / [nk-debug](../nk-debug/SKILL.md)。

## 3. 查重与历史判断

定向搜索相关 open/closed Issue、已有 backlog、代码能力、发想与 solutions；按概念和行为匹配，不只匹配用户措辞。复用已有检索覆盖，不扫描无关全库。未选中的发想不等于已否决，关闭 Issue 也不等于功能已实现。

| 结果 | 动作 |
| :-- | :-- |
| 已有同题记录且无新信息 | 返回链接与覆盖理由，不重复创建或评论 |
| 已有同题记录且有新证据、范围或复现信息 | 在授权范围内补充既有记录；显式更新请求不因“查到自身”而结束 |
| 需求已实现且覆盖当前请求 | 给出依据并结束；若存在行为差异或回归，针对真实缺口继续 |
| 历史上否决或已沉淀 | 核对当时理由和当前条件；仍适用则说明，不重复落档；新证据或条件变化可支持重议，但不得静默推翻已定决定 |
| 无同题记录且值得跟踪 | 创建新记录，保留必要历史关联 |

同题 Issue 已关闭但出现回归或新条件时说明差异，按项目惯例与授权选择补充、重开或新建关联问题；没有相应授权不自动重开。查询失败不等于不存在：说明查重缺口，不能盲目重试创建。

## 4. 创建或更新

读 [Issue 生命周期与写作规范](../conventions/issue-writing.md)，按其格式、标签和来源规则成文；用稳定接口与行为表达问题，不堆实现步骤。Bug 写 Evidence，区分已确认与待验证；验收描述可独立核对，构想类不强造验收清单。

- **GitHub 目标可用且有授权**：新事项创建 Issue；既有事项默认追加有增量的证据评论，不覆盖原描述和他人内容。用户明确要求改写正文时保留仍有效的讨论与边界。
- **无 GitHub 远端**：按约定写入或更新 docs/backlog.md，先查重，保护已有条目。具体字段不另造一套。
- **有目标但网络、认证或权限失败**：报告阻断并保留草稿，不把暂时失败当作无远端而私建第二套待办。请求结果不明时先查询确认是否已创建，再决定是否重试。
- **未获写入授权或只要草稿**：直接返回可审阅内容与目标，不发送、不写 backlog。

写入后读取结果或核对返回内容，确认目标、标题、正文与链接；不自动修改 assignee、关闭无关 Issue 或启动实现。

## 5. 返回当前任务

返回链接/位置、创建/补充/复用/未落档的实际动作、证据与未决项。嵌入调用交回同样结果，由调用方继续原任务；独立调用则汇报结束，不要求切换会话，也不自动开始新 Issue 的工作。

若写了 backlog，明确文件范围与未提交状态，返回已有交付协调方，随对应交付通过 [nk-commit](../nk-commit/SKILL.md) 入库；没有协调方时暂留。用户显式要求提交或保存现场时按相应公开入口执行，本技能不自行维护 current 或生成额外交接提交。
