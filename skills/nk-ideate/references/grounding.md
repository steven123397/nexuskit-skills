# Phase 1 扎根

由入口在 Phase 1 加载。本文件定义临时目录、材料路由、各模式的角色方法、扎根摘要及模型档位；条件材料由入口加载，全部适用结果合并后返回入口。

## Phase 1：按模式扎根

派发时同时传入选中方法的绝对路径，保留材料来源。

生成想法之前先收集扎根材料。派发集合取决于 Phase 0.3 选定的模式。网络调研和用户调研材料的处理在所有模式下都运行（尊重跳过用语）。经验检索在仓库模式和仓库外软件模式下按知识库是否存在运行，**在非软件模式下默认跳过**——`docs/solutions/` 里存的是工程经验，不适用于命名、叙事、个人或非数字化商业话题。

**Surprise me 模式的扎根深度。** Surprise me 模式下扎根比指定主题更深——套用 [scope-gates.md](scope-gates.md) 0.2 表中 `1 扎根` 一行；运行 Issue 分析时，把 Issue 主题作为一等输入，而不是脚注。指定主题时保持较浅的扫描：用户指定的主题决定了什么相关。

**先确定临时目录。** 生成一个 8 位十六进制的 `<run-id>`，本次运行的网络调研缓存、Phase 2/4 的检查点都复用它。临时目录位于系统临时目录下的 `nk-ideate/<run-id>/`（例如 Windows 的 `%TEMP%`、类 Unix 系统的 `$TMPDIR` 或 `/tmp`），用当前环境可用的文件写入能力创建，记下它的绝对路径，下文称 `<scratch-dir>`。不要放在目标仓库或用户的当前目录里。运行结束后**不删除**它：网络调研缓存会在同一会话后续的发想中跨 run-id 复用；无仓库时发想记录本身也写在这里。清理交给操作系统。

**在两个派发块之前，先对提示或问答中提到的每个文件做调研材料路由检验**（见下文"用户提供的调研材料"）。必须放在两个派发块之前，因为两边都有办法把一个证据文件吞进去：仓库扫描会把用户点名的根目录 `*.md` 读进 `User-named references`，仓库外的材料综合会读"所有丰富的提示材料"。不做检验，一份很长的调研报告或分析导出就会同时被送去综合*和*提炼，内容重复并污染 `Topic context`。每个文件只走一条路。

检验产生证据材料时，先返回入口加载提炼方法，再安排派发；材料提炼与其他扎根并行，不等其他工作完成才启动。

**回传体量。** 按 [`../../conventions/subagent-results.md`](../../conventions/subagent-results.md) 处理；沿用本阶段摘要上限与临时目录。网络缓存保存约定的摘要文本，不只存文件路径；候选卡片的完整回传要求见 [divergent-ideation.md](divergent-ideation.md)。

扎根代理并行、在**前台**运行（不要放后台——Phase 2 需要结果）。不支持子代理时，主会话依次完成下列每一项，产出同样结构的摘要。

**仓库模式派发：**

1. **快速上下文扫描** —— 派发一个通用子代理，有已知的模型覆盖参数时用最便宜的可用模型，否则继承。按上面的路由检验，已判为证据的点名文件放到提示的调研材料一行，而不是 `User-named references`。派发提示：

   > **扎根范围：** 利用已提供的项目背景，直接找与关注点相关的现有模式、痛点、杠杆点、适用的工作流约束；Surprise me 模式下还包括有代表性的文件和近期活动。关注点无法确定范围时，做一次有针对性的根目录或工作区探查。
   >
   > 从关注点或调用方背景点名的文件和区域开始。运维规则影响扫描时，读当前适用的项目指令（`AGENTS.md` 及其指向的工作流文档）；需要对齐产品方向时读 `STRATEGY.md`（没有时才读 `PRODUCT.md` 或 `VISION.md`）；需要规范术语时读 `CONCEPTS.md`；需要了解当前状态时读 `docs/current.md`。
   >
   > 如果关注点点名了一个根目录 `*.md` 文件，读它并把相关内容放在 `User-named references` 下。如果该文件出现在下面的调研材料一行，把完整提炼留给调研代理，这里只写一行概要。
   >
   > 返回一份简明摘要（40 行以内；点名参考文件有实质内容时可以更长），包括：
   >
   > - 与关注点相关的现有模式与惯例
   > - 与关注点相关的痛点或缺口
   > - 可能的杠杆点
   > - 如果读了产品文档，相关的产品方向与边界
   > - `User-named references` 一节（当关注点点名了根目录 `*.md` 文件时）
   >
   > 保持扫描浅层。不要分析无关的 Issue、模板、贡献指南或代码。
   >
   > 关注点：{focus_hint}
   >
   > 调研材料（仅在 `Additional context` 下写概要——不要完整读取；另有代理负责提炼）：{research_artifact_files，或 "无"}

2. **经验检索** —— 按下文“经验检索前置检查”决定是否加载提示词与派发。

3. **网络调研**（默认开启；跳过用语与缓存处理见下文"网络调研"）。

4. **Issue 分析**（条件性）—— 入口识别到 Issue 意图时加载分析分支。扫描可以与其余扎根并行；有聚类任务时，等主题及覆盖统计返回再合并摘要。范围问题由主会话处理，子代理不能代替用户决定。

**仓库外模式派发（跳过代码库扫描；用户提供的材料是主要扎根来源）：**

1. **用户材料综合** —— 派发一个通用子代理（最便宜的可用模型），读取 Phase 0.4 问答得到的用户材料以及丰富的提示内容——**不包括路由检验判为证据的文件**，那些交给提炼代理，不能同时进入综合——返回一份与代码库扫描同构的结构化扎根摘要（项目形态 → 话题形态；显著模式 → 已声明的约束；痛点 → 用户点名的痛点；杠杆点 → 材料暗示的机会切入点）。这样 Phase 2 的子代理不必关心扎根来源。

2. **经验检索** *（仅仓库外软件模式）* —— 按下文前置检查处理；非软件模式默认跳过。

3. **网络调研** —— 与仓库模式相同（见下文）。

Issue 分析不适用于仓库外模式。

### 经验检索前置检查

先用文件列表确认目标仓库的 `docs/solutions/` 是否有可检索文档；不存在或为空时，不加载 [../../conventions/agents/learnings-researcher.md](../../conventions/agents/learnings-researcher.md)、不派发空检索，在摘要中注明无已有经验。`CONCEPTS.md` 若存在且与主题相关，仍由上下文扫描或主会话按需读取；词汇输入不依赖经验代理。

有文档时才读取 [../../conventions/agents/learnings-researcher.md](../../conventions/agents/learnings-researcher.md)，以该方法加关注点或话题概述派发：从全部经验类型中找以前的尝试、约束、痛点、成功和失败做法及机会，不限于设计模式。直接返回至多 5 条相关经验，保留来源、适用条件、关键启发；没有匹配时说明检索范围。只看目录是否有内容，不在主会话预读全库。

### 网络调研

两种模式下默认开启。用户在请求或之前的回答中说了"不做外部调研"、"跳过网络调研"或类似说法时跳过；此时不派发 `web-researcher`，并在合并后的扎根摘要中注明已跳过。

入口加载网络缓存方法后，先检查本会话已知结果是否适用；仅对未命中或需要刷新的研究派发，完成后按该方法写回。

派发网络调研时，读 [../../conventions/agents/web-researcher.md](../../conventions/agents/web-researcher.md)，以该方法作为通用子代理的种子，附上本技能目的：寻找先例、相邻方案、市场信号、跨域类比和机会，优先发散信号，仅在影响可行性时涉及实现约束。按 [网络调研摘要](../../conventions/research-digest.md) 直接返回摘要，供扎根合并和缓存复用。传入关注点、一两句话的背景概述和模式。不要传代码库内容——这个提示只面向外部。有已知的模型覆盖参数时用中档模型；否则不传覆盖参数，继承当前模型。

### 用户提供的调研材料

当提示或问答点名了一个*收集来的证据*文件时适用于所有模式——社交舆情或搜索调研报告、问卷导出、分析数据导出、访谈记录——不论路径在仓库内还是仓库外。

**路由检验（指令 vs 证据）—— 在派发 Phase 1 快速上下文扫描之前执行。** 一个点名文件属于*指令*：忽略或违背它的想法就是错的（一份规格、一张待办清单、用户希望回应的反馈）；仓库模式下它走 `User-named references`，在派发时放进 `<constraints>`。一个文件属于*证据*：它是关于外部世界的信号，想法可以引用它。调研材料都是证据：进入证据层，永远不进 `<constraints>`——按热度排序的讨论只能启发想法，不能否决想法。每个文件只走一条路，不会两条都走；检验必须在扫描之前完成，扫描才知道哪些文件不要碰。

证据材料按入口加载的提炼方法处理；已派发提炼时等返回再合并，放在 `User-supplied research` 下，与网络调研分开，保持来源可见。

### 合并后的扎根摘要

把所有派发结果合并成一份简短的扎根摘要，使用以下各节（没有产出的节省略）。合并完成后，Phase 1.5 会在同一份摘要后追加 `Topic axes` 一节：

* **Codebase context** *（仓库模式）* —— 项目形态、显著模式、痛点、杠杆点；或 **Topic context** *（仓库外模式）* —— 话题形态、已声明的约束、用户点名的痛点、机会切入点
* **User-named references** *（仓库模式）* —— 用户点名的指令文件中适用于本主题的规则原文与来源；保留必要上下文，不把无关整份文件复制到每次派发。Phase 2 视为约束
* **Additional context** *（仓库模式）* —— 发现但未被点名的根目录 Markdown 的一行概要。Phase 2 视为背景，不是方向
* **Past learnings** —— 来自 `docs/solutions/` 的相关经验
* **Issue intelligence** *（有时）* —— 主题概述以及聚类调用的覆盖统计（见 [issue-intelligence.md](issue-intelligence.md) §d）
* **External context** *（运行了网络调研时）* —— 已有做法、相邻方案、市场信号、跨领域类比。缓存提供结果而非新派发时注明"（复用之前的调研）"
* **User-supplied research** *（有时）* —— 档案概要与路径，或小材料的内联内容；与 External context 分开，保持来源可见

**失败处理。** 扎根子代理失败时"提示并继续"——不因扎根失败而阻塞。网络调研失败（网络问题、工具不可用）时，记录提示（"外部调研不可用：{原因}。仅使用内部扎根继续。"）并继续。仓库外模式的问答没有得到可用材料时，在扎根摘要中注明材料单薄，让 Phase 2 子代理用更宽的生成来弥补。

## 模型档位（适用于本技能的每一次派发）

子代理派发按任务形态分档，不写死模型名：

* **提取档** —— 证据侦察和其他检索/摘录类工作。客户端提供已知的模型覆盖参数时用最便宜的可用模型；仓库很大或技术栈生僻时升到生成档。
* **生成档** —— 基于证据的发想视角和依据核查。有已知覆盖参数时用中档模型。
* **最高档** —— 最高档发想视角、交叉组合和最终裁定。不传模型参数，继承编排者的模型。

不知道模型名时不传覆盖参数，继承当前模型，不要猜。

**降级规则。** 客户端的子代理机制不支持按代理选择模型时，所有派发都用继承的模型，但保留阅读预算和档案上限——此时成本控制来自结构，而不是分档。

每次派发被拒绝时，按是否已有代理启动来分类：启动前的参数错误修正一次；容量受限的工作排队等待；其他失败走该阶段写明的降级路径。

有两种覆盖会把整个发想编队提到最高档：Surprise me 模式和 `go deep` 深度覆盖（Phase 0.5）。

合并摘要、证据索引与降级信息返回入口，再开始拆轴。阶段内仅 Issue 分支可按其规则补问范围，复用入口的提问方式。
