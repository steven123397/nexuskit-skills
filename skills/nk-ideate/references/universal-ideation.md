# 非软件发想的领域适配

主题与任何软件制品无关时使用：独立命名、叙事、个人决策、非数字化商业策略或实体产品。页面、应用、功能和软件产品的文案、UX、定位仍走软件路线。

Phase 0 只按“执行方式”选深度；Phase 1 仓库外扎根之后再应用领域差异。这里不再启动一轮访谈。用户补充使主题实质变化时，按 `scope-gates.md` 重新评估受影响的路由，只补缺失的扎根材料。

## 执行方式

保留快速、标准、完整三个深度：快速用于一组起步想法，标准用于常规探索，完整用于明确要求深入探索的请求。tactical 优先采用快速或标准；`go deep` 采用完整并取消 tactical。依据已有请求决定，不为选档额外提问。

快速和标准由主会话内联覆盖六视角；完整每个视角独立派发，档位按 `grounding.md`，`go deep` 使用最高档。此差异只改变执行方式，不另定义生成或筛选流程。

沿用 Phase 1.5 的拆轴结果与 `decomposition.md` 的跳过标准。非软件主题不做仓库证据侦察；名字、标语、单个情节通常不可拆，品牌策略可按材料中的不同关注点拆轴。

## 共用流程与领域差异

Phase 2 按 `divergent-ideation.md` 执行六视角、数量与预算、候选格式、合并去重、交叉组合、轴覆盖和检查点；编队仅使用上面的非软件执行方式。Phase 3–5 按 `post-ideation-workflow.md` 执行核查、筛选、写入与交接。派发时附上这些领域差异：

- 扎根于用户材料和适用的外部研究，不读取无关仓库；已有经验默认跳过工程经验库。
- 将六视角和“值得团队讨论”转换为主题本身的语言，例如创意是否值得展开、个人选择是否值得认真权衡；tactical 的门槛免除照常适用。
- 保留依据强度、新颖性、预期价值、可行性和代价等共同筛选标准；实现成本、产品改进等软件表述按领域替换。例如命名看辨识度、表达效果和受众契合，叙事看冲突与连贯性，个人决定看价值观、现实约束和可逆性。只采用与本次判断有关的标准。
- 核查者对照用户材料与外部来源检验依据，仍与生成分离；无法独立核查时按共用流程披露降级。不要为满足数量降低依据标准。

领域适配随现有派发内容传入，不要求每个代理再读一套流程。共同的候选、留存和补充生成数量只由 `divergent-ideation.md` 的“数量与预算”定义。

菜单中的 `nk-brainstorm` 是可选的进一步展开，例如把名字展开成品牌简报、把情节展开成大纲；不自动进入 `nk-plan` → `nk-work` 实施链。
