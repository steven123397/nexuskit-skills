# 合并前检查

仅明确的 pre-merge 请求使用。检查已完成工作的组合关系，不能替代缺失的单元审查或必要测试。本材料持有定界、聚焦检查与主会话复核，完成后返回入口第 5 步写报告。

## 1. 固定对象并复用证据

优先复用调用方提供的实际合并目标、累计 diff 基线、被审快照、文件清单、Plan 与临时纳入工作、已有单元审查及验证结果。范围缺失时只补相关 Git/项目事实；合并目标取用户或项目约定，不能直接采用功能分支的同名 upstream。无法确定时返回范围缺口。

核对 merge-base 与目标分支当前提交，阅读累计 diff 和提交清单；按风险查看受影响的调用方、接口及配置，不只读报告摘要。单分支项目用调用方确认的 Plan 起点和范围，不把同期其他工作混入。明确纳入的未跟踪文件按全文读，其余排除并报告。记录 HEAD、基线及纳入工作区内容或指纹；分析期间不改被审内容。

把验收要求与已有证据对应起来：证据覆盖了什么、针对哪个快照、后来哪些变化可能使其失效。已有合并前检查仍覆盖当前范围时可复用结论，不制造重复轮次；有变化时补查其影响链，不能只复核修改行。目标分支后续变化可能影响兼容性时检查交汇接口，缺少合并结果的真实验证须披露，不声称已经验证合并。

关键单元缺少项目要求的审查或集成证据时，列出具体缺口；可继续完成其余只读检查，但结论必须为未完成或存在阻断，不能用本路径顶替。

## 2. 四项聚焦检查

| 问题 | 具体核对 |
| :-- | :-- |
| 整体目标是否闭环 | Plan 最终行为、验收条件和明确调整是否落地；临时 Issue/需求有无改变承诺或留下断层 |
| 单元之间是否一致 | 生产者与消费者的接口、状态、数据流、错误语义及配置约定；跨单元的调用是否真正接通 |
| 后续改动是否破坏已有结论 | 公共模块、依赖、迁移、临时修复是否改变前面单元的前提；原测试/审查是否仍适用 |
| 组合后是否遗漏 | 迁移/启动接线、旧入口、发布配置、文档契约与集成验证；测试或 CI 调整是否使已有绿色结果失去证明力 |

不重复逐行挑选已充分审查的局部实现，不重议没有新反证的已接受取舍，不扩成全仓重构。发现跨单元重复可直接报告有实际影响的结构问题，不启动 simplify 全流程。纯风格偏好、收益不明确的改写不作为收尾阻断。

## 3. 按缺口选择零到两个代理

默认主会话完成。只有具体、可独立调查且确有收益的缺口才派只读专项代理：一个缺口用一个，两个独立风险面最多两个。一次合并前检查最多派发两个子代理，不通过分批、重试或更名绕过上限，不允许代理再派生；无能力或被禁止委派时由主会话查证，无法补齐则报告缺口。

任务包包含同一快照、明确问题、相关接口/差异、已验证证据和已接受取舍；相关经验带原始路径、适用条件及验证影响。只加载该问题必要的材料，不加载常规编队或另行输出全套审查。每项返回问题、实际后果、证据位置、建议与置信边界；无发现和无法判断分别说明。代理不得写文件、改状态、建票或提交。

若需要超过此预算的系统性审查，返回风险范围和所需后续，不自动切换常规路径，不启动 simplify 或独立 validator。

## 4. 主会话核实与返回

主会话核对每个候选的原文、可达影响与当前证据，合并相同根因，区分已证实缺陷、待查假设、缺少验证和已接受延期。未经证实的风险不能包装为确定缺陷；有事实矛盾的延期仍报告，不自行改写决定。

按实际后果分级：P0 阻断，其他发现是否阻断取决于本次交付条件与已有决定；不能因编号较低就自动延期，也不能因只是精简建议就一律强制修复。缺少必需审查或验证覆盖时不得给出无条件通过。

返回入口写报告，明确“主会话合并前检查”、使用的零到两个代理、四项检查覆盖、基线与快照、复用依据、发现和未验证项。不称为独立全面审查。后续复核沿用本路径，核对原发现、修复影响及新增风险；被审内容未变的部分复用证据。
